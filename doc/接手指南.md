# 接手指南

先看本文件了解业务，再读 [项目架构](项目架构.md)。启动和部署查根目录 [项目说明](../项目说明.md)。

## 产品只有三条主线

- 学习：已发布录音 → 转写与点评 → 听录音答题。
- 陪练：选场景 → 文字对练 → 评分与推荐话术。
- 考核：知识题、录音题、对练题 → 交卷评分。正式对练考试禁用求助，自测可用。

员工可用浏览器登录 H5；管理员负责账号审核、录音发布、题目审核和成绩查询。当前开发和验收以文字对练为主，已有语音输入与播放保留为可选能力。

## 场景和评分怎么改

`background/goal` 是员工任务，`persona` 是客户画像，`opening` 决定谁先开口，`state_rules` 控制信任与结束条件，`scoring` 引用评分表。

一轮执行：员工发言 → 模型评估 → 代码限制信任变化、判定结果 → 客户回复。`deal` 表示达成场景目标，不一定指销售成交。结束后教练给维度分，代码按权重换算并扣求助分；催收场景还可设置红线封顶。

S01～S03 是客服示例；C01～C06 是贷后沟通示例。均需业务确认。Stub 只用于联调，其关键词规则不能代表真实模型效果。

修改配置后，在 `backend/` 执行 `uv run python -m app.cli check-scenarios`。

## 知识库怎么改

先看「知识案例」中的智能清洗分流与培训改编，普通结果作为候选，重大问题再人工处理。改编允许调整表达和教学衔接，不能当成原文事实。

真实转写事件在管理后台的「知识案例」（`/admin/knowledge-events`）核对：选择事件 → 对照左侧上下文或完整转写 → 点击证据编号定位 → 修改右侧标签、总结、适用边界 → 保存待审核、通过或驳回。驳回须填写原因。

原始提取结果只读，人工修订和审核历史另存。修改已通过内容后重新保存会回到待审核；通过审核仍不启用检索，也不替代隐私、角色与政策核验。

`knowledge/客户服务话术.md` 对应 S02/S03，`knowledge/投诉处理话术.md` 对应 S01。文件头的 `title/tags/scenarios` 描述资料，`##` 二级标题划分片段；场景列表为空表示通用资料。

在 `backend/` 执行 `uv run python -m app.cli ingest-knowledge` 导入。知识目录只放业务资料，说明文档放 `doc/`，避免误导入。若数据库曾导入英文旧文件名对应的资料，重新导入前需核对并清理旧来源记录，避免重复；本次仅改文件，未修改数据库。

示范中的故障、处理进度和回访时间都是虚构情境，正式使用前按实际流程审核。

## 录音与考试怎么读

录音来源在 `services/recording_source.py`，文件转写在 `file_asr.py`，分析、发布和知识同步在 `recordings.py`。

在 `backend/` 执行：

```bash
uv run python -m app.cli import-recordings --file ../data/private/recordings.json
uv run python -m app.cli process-recordings --limit 5
```

真实清单留在私有目录，处理成功后仍需审核发布。配置查 `backend/.env.example`。

试卷从 `exams/papers/T01_compliance_self_test.yaml` 读起，再看 T03 的情景对练和 E01 的正式考试配置。`quiz/listening/roleplay` 分别是知识题、录音题、对练题；组卷和交卷在 `services/exams.py`，判分在 `exam_rules.py`。

听录音题不足时可能跳过该部分，需实际验证完整试卷。现有题库与评分表不是已确认的公司正式制度。
