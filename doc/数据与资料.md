# 05 数据接入与安全

## 当前数据链路

以优秀录音为唯一真实案例入口，优先复用已有转写。先按来源标识去重并保留完整导入快照，再提取连续沟通事件；当前不涉及 Wiki。

| 层次 | 保存什么 |
|---|---|
| 案例 | 来源标识、导出快照、原文哈希、原始片段编号/声道/时间值、角色映射及核验状态 |
| 知识事件 | 原文范围、必要上下文、证据编号、提炼总结、标签、适用边界、审核及检索状态 |

标签先限定为四类：客户问题、沟通阶段、坐席动作、可观察结果。允许“其他/无法判断”，优秀标签保留为源系统标记，不直接视为片段结论。

保留否定、不确定、纠正和后续反应；重复语气词可在展示时折叠，原始快照不删除。总结与原话分开，沟通反馈与还款/审批结果分开。角色未核验、关键 ASR 存疑或具体政策未核验的内容不得直接成为正式答案。

私有试标见 [试标说明](../data/private/knowledge-pilot/试标说明.md) 和 [结构化示范](../data/private/knowledge-pilot/提取示范.json)：两份已有转写快照、三个事件已导入本地库，全部待审核且未启用检索。

## 数据放在哪里

| 位置 | 保存内容 | 是否提交 Git |
|---|---|---|
| 原业务库 | 优秀录音与已有转写，MCP 只读查询 | 不适用 |
| `data/private/` | 原始导出、完整本地样本、人工试标 | 否 |
| PostgreSQL `transcript_snapshots` | 完整基础脱敏转写、原片段编号、声道、时间值、来源及版本 | 否 |
| PostgreSQL `knowledge_events` | 提取事件、证据编号、标签、总结、适用边界、审核状态及 pgvector 向量 | 否 |
| `doc/`、`AGENTS.md` | 说明、开发规范与非敏感数据库字典 | 是 |
| `prompts/`、YAML 配置 | 提示词、场景、评分标准 | 是 |

向量与业务数据在同一个 PostgreSQL 中，不额外部署向量数据库。数据库使用 Docker 数据卷持久化；应另做数据库备份，私有 JSON 不能替代完整备份。

### 已有转写导入

在 `backend/` 执行：

```bash
uv run python -m app.cli init-db
uv run python -m app.cli import-transcripts --file ../data/private/knowledge-pilot/提取示范.json
```

命令读取本地 JSON，不重新转写，也不调用外部模型。输入格式见 `services/transcripts.py` 中的 `ImportBatch`：案例保留完整片段，事件引用案例及编号。未声明的原始全文副本、输入审核状态不会入库；文本先做基础脱敏。

- 同一来源和原文哈希只存一份快照；原文变化新增版本。
- 同一快照的同一事件与提取版本重复导入不新增；提取内容变化新增事件版本，不覆盖旧结果。
- 总结与原片段分开保存，完整上下文通过快照和片段范围还原。
- 导入在一个事务内执行，默认 `privacy_status=pending`、`review_status=pending`，向量为空。角色、时间单位和政策核验状态照实保留。
- 基础脱敏不保证去除姓名、地址等全部信息；仍需人工核验，不把待核验文本发给外部模型。

### 当前边界

已完成存储、导入和管理员核对页面（`/admin/knowledge-events`），支持人工修订、保存待审核、通过和驳回。`review_data` 与原始提取分开；`review_history` 记录每次操作及修订内容；`review_revision` 防止旧页面覆盖新修改。保存修改会重新待审核，修改时清空旧向量。

版本启用/撤回、隐私核验操作、向量生成和真实事件检索尚未接通，因此通过审核也不会直接供求助或点评使用。三个真实试标事件仍保持待审核。

迁移核对：新增两表已与 ORM 定义核对一致。全库 `alembic check` 仍会报告旧业务表注释、索引及 LangGraph 自管表的历史差异，不能直接据此生成删除操作。

现有 `knowledge_chunks` 仍支撑示例 Markdown 与旧录音亮点检索；`knowledge/` 仅保留开发示例。正式事件后续以 `knowledge_events` 为准，先迁移原检索入口并移除示例干扰，再启用真实数据，避免两套来源混用。

| 数据 | 存放与使用 |
|---|---|
| 虚构场景、示例话术、题库 | `scenarios/`、`knowledge/`、`exams/`，可提交 Git |
| 本地原始资料 | `data/private/`，禁止提交 Git |
| 真实录音 | 音频保留在对象存储；系统数据库保存地址和处理结果，需权限控制 |
| 转写、点评、题目 | 转写按现有规则脱敏后落库；分析结果和发布内容还需人工审核 |
| 密钥 | `.env`，禁止写入代码、日志或演示画面 |

录音处理：授权来源 → 导入地址 → 转写脱敏 → AI 分析 → 人工审核 → 发布学习内容与知识片段。取消发布会移除对应录音知识片段。

脱敏函数不能保证识别所有姓名、地址或业务秘密，演示资料必须人工检查。音频本身不会因转写脱敏而自动脱敏；视频使用虚构或已脱敏且获准展示的素材。

知识库中的示范时间、技术进度和处理方式是虚构情境，不能作为真实业务事实或权限承诺。正式资料应经业务确认，保留来源与适用条件。
