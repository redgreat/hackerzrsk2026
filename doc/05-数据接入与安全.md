# 05 数据接入与安全

培训话术由后台维护，原稿保存在 `knowledge_scripts`。启用的话术同步到 `knowledge_chunks` 供教练检索。导入导出的是原稿 JSON，导入后会重建对应检索片段。

## 来源与存储

优秀录音表是案例索引。试标阶段通过 DBMCP 只读查询，按催记 ID 整理优秀标签并关联已有质检转写。已用本地导出的两份完整转写和三个带证据编号的事件验证导入。字段关系见 [字段目录](dbmcp/database-selection.html)。

历史导出与试标放在 `data/private/`。后台可按需从 DBMCP 导入录音与已有 AI 转写。PostgreSQL 的 `recordings` 保存录音地址和关联快照，`transcript_snapshots` 保存基础脱敏后的转写，`knowledge_events` 保存事件范围、标签、总结和适用边界。重复导入按通话录音 ID 复用录音，同一版本的转写也会复用。

应用后端通过 `backend/.env` 中的 `RECORDINGS__DBMCP_KEY` 访问 DBMCP。后台导入以 `recall_call_record.id` 为去重标识，并取对应催记最近一次成功的 AI 转写。导入会保留管理员已设置的发布状态和学习内容。

## 获取可访问的录音 URL

从催记定位 `recall_call_record`，同时查询 `source`、`callCenterPath` 和 `url`。对于 `source=3` 且 `url` 以 `amp-prod/` 开头的记录，使用 `RECORDINGS__AUDIO_BASE_URL` 拼出完整地址。实际存储域名通过同批通话和质检明细中的完整地址核对，配置在本地 `backend/.env`。

用带 `Range` 请求头的 GET 检查首段数据。检查通过的完整 URL 放在私有清单 `data/private/dbmcp/verified-recording-urls.json`。如果主地址失败，可校验同一通话记录中的备用字段。样本 08 的主地址返回 404，备用地址返回 WAV 数据。音频格式以实际响应为准。

需要入库时，从 `backend/` 执行 `uv run --locked python -m app.cli import-recordings --file ../data/private/dbmcp/verified-recording-urls.json`。录音和已有 AI 转写分开入库，管理员在录音详情关联快照。录音派生练习的发布与撤回遵循 [产品方案](02-产品方案.md#录音与练习发布规则)。

## 提取、清洗和审核

1. 选取连续对话，保留客户的问题、坐席的动作及后续反应。可用安抚、规则解释、问题拆解、方案推进和行动确认等维度标注。
2. 从 `backend/` 使用 `python -m app.cli import-transcripts --file <私有JSON路径>` 导入。录音练习的转写核对及生成结果审核在后台「优秀录音」完成。
3. 人工准备单事件去标识输入，保留角色和片段编号。通过 `python -m app.cli clean-training --file <私有JSON路径>` 整理重复、修正有依据的表达，并将教学新增内容标出。程序校验引用与角色，存在重大问题时转人工查看。
4. 清洗结果保存在 `training_cleanups`，含模型版本、改编对话和问题。试跑 P02 时曾发现模型把含混原话改得过于确定，审核需重点复核这一类内容。

## 使用边界

审核状态与检索启用分别记录。「培训候选」表示通过本次清洗检查。新事件向量字段已预留，现有教练求助与点评仍走已有话术检索。制度用语需有业务依据，客户口头同意和实际办理结果分别记录。比赛使用获准展示的脱敏资料，原始录音、客户标识和密钥留在私有配置或资料中。
