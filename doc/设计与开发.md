# 设计与开发

## 1. 跑通陪练

本地用 Docker 启动 PostgreSQL，FastAPI 托管 Vue 构建产物。文字对练已跑通登录、选场景、发送消息、求助、结束和查看报告。场景与评分表使用 YAML，LangGraph 负责对话步骤，代码规则计算结果。启动命令见[项目说明](../项目说明.md)。

## 2. 接入优秀录音与已有转写

优秀录音表作为真实案例入口。通过 MCP 只读查询，按催记 ID 合并优秀标签，关联已有质检转写。现有录音导入代码可以查询录音地址。已有转写这条链路已用本地导出完成试标和入库，MCP 自动同步转写尚未实现。

原始导出与试标放在 `data/private/`。本地已导入两份完整转写和三个带证据编号的事件。PostgreSQL 中 `transcript_snapshots` 保存基础脱敏后的完整片段和版本，`knowledge_events` 保存事件范围、总结、标签和适用边界。重复导入同一版本不会新增。导入使用 `python -m app.cli import-transcripts --file <私有JSON路径>`，从 `backend/` 执行。数据库表结构可查[字段目录](dbmcp/database-selection.html)。

## 3. 从原文核对提取结果

管理后台「知识案例」可定位证据、对照完整转写、修订标签和总结，并记录通过或驳回。人工修订单独保存。此页现在用于定位重大问题和抽查提取质量。审核状态与检索启用状态各自独立。

## 4. 用千问清洗与改编

目前由人工准备单个事件的去标识输入，保留片段编号、角色和完整事件上下文。运行 `python -m app.cli clean-training --file <私有JSON路径>`。模型整理重复和口语，修复有依据的表达，保留否定、条件和纠正。允许新增教学衔接，新增行单独标记，原文支持的行引用片段号。程序校验引用、角色对应和新增标记，发现重大问题则分流到人工处理。

结果写入 `training_cleanups`，保留去标识输入、改编对话、修改说明、问题和模型版本，后台可查看。P02 已用千问试跑，保留了日期不确定性，也发现含混原话被推测性改写。当前「培训候选」只表示通过当前清洗检查。原始转写、人工修订和改编分别保存。新事件的向量字段仍预留，员工求助与点评仍用现有检索。

## 后续方向

先确定培训材料的采用依据，明确训练目标、必要背景、员工任务、可观察的评价标准和证据边界，再用少量案例判断适合做辨析题、短练习还是完整陪练。标准验证后，再考虑批量处理、向量检索和接入点评。

参赛围绕实际验证的流程录制不超过 5 分钟的视频，配语音或字幕。邮件标题和附件按「作品名称+姓名+工号」命名，正文写背景、实际成果及设计与应用时间。演示只使用获准展示的脱敏素材。
