# 05 数据接入与安全

> 主数据方向是复用业务系统中已采购的成熟话术。能播放或转成文字不代表自动获得了二次训练、导出或衍生使用权；接入前必须确认合同授权、接口能力和数据范围。

## 1. 可能接入的数据源（待评估）

| 数据源 | 用途 | 接入方式（候选） | 状态 |
|---|---|---|---|
| 公司其他参考项目 | 复用现有能力（如模型网关、企业微信 SDK、知识库） | 代码复用 / 服务调用 | 待评估 |
| 业务系统成熟话术（音频/转写） | 求助提示、评分依据、推荐话术、候选场景 | 授权导出/API → 脱敏审核 → RAG 知识库 | **主数据源，待确认授权与接口** |
| 服务手册、流程与权限边界 | 约束解决方案和合规表达 | 审核后进入 RAG 知识库 | 待评估 |
| 客户信息（画像类） | 生成更贴近真实的客户画像 | **仅使用脱敏、聚合后的特征** | 待评估 |
| 历史通话/聊天记录 | 提炼常见异议与应对 | 离线脱敏后人工/AI 提炼 | 待评估，涉及 CRM 规划需协调 |

## 2. 客户信息使用原则

1. **最小必要**：只取构造画像需要的特征（行业、规模、关注点、常见异议），不取身份信息。
2. **先脱敏后使用**：任何进入提示词、知识库、日志、演示视频的数据都必须是脱敏后的。
3. **聚合优先**：优先使用"某类客户的共性特征"，而不是某个具体客户的记录。
4. **不出公司边界**：若使用外部模型 API，传入内容不得包含可识别的客户信息；涉及敏感数据时优先考虑公司私有部署模型。
5. **授权确认**：接入前需确认数据归属部门同意，并符合公司保密制度。

## 3. 成熟话术转为陪练经验的处理链

1. **确认权利**：确认采购合同是否允许导出、内部二次加工、模型处理和比赛演示；仅有播放权或转写权时不能默认可用于 RAG。
2. **取得文本**：优先使用原系统提供的授权转写/API；没有接口时先以少量人工整理文本完成 MVP，不抓取或绕过访问控制。
3. **脱敏清洗**：删除真实客户、员工、联系方式、订单号和业务秘密；纠正 ASR 错字，去掉无业务价值的寒暄。
4. **专家筛选**：标记“推荐”“禁用”“仅特定场景可用”，补充适用条件和权限边界。真实录音中的一句话不因出现过就自动成为标准话术。
5. **结构化入库**：按主题整理为 `knowledge/*.md`，通过场景 ID、标签和标题限定检索范围，运行 `ingest-knowledge` 入库。
6. **使用与追溯**：知识仅用于求助提示和教练复盘，不直接替员工做业务承诺；记录来源版本和审核人，变更后重新导入。

## 4. 脱敏规则（草案）

| 字段类型 | 处理方式 | 示例 |
|---|---|---|
| 客户/公司名称 | 替换为虚构名称 | 某某科技 → 华东某制造企业 / "星河科技" |
| 联系人姓名 | 替换为姓氏+职务 | 张三 → 张经理 |
| 手机号、邮箱、地址 | 删除 | — |
| 合同金额、报价 | 区间化或按比例缩放 | 38.6 万 → 30~50 万 |
| 项目编号、合同号 | 删除 | — |
| 内部员工信息 | 删除或替换 | — |

## 5. 仓库与存储规范

- 真实/原始数据只放 `data/private/`（已加入 `.gitignore`），**禁止提交**。
- 仓库中只保留虚构或已脱敏的示例数据（如 `scenarios/*.yaml`）。
- 密钥只放 `config/config.yml`（不入库），不得出现在代码、文档、日志、截图中。
- 对话记录落库时只存工号，不存员工手机号等个人信息；日志中不打印完整对话内容。

## 6. 比赛材料合规检查清单

- [ ] 演示视频中无真实客户名称、金额、联系方式
- [ ] 截图中无企业微信真实通讯录、群聊信息
- [ ] 提示词/知识库展示片段已脱敏
- [ ] 未使用未经授权的第三方内容（图片、音乐、话术版权）
- [ ] 已确认成熟话术可用于内部 AI 检索、改写和比赛演示，而不只是可播放/转写
