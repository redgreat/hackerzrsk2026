# 参赛开发重点

## 目标

做一个员工容易使用的「AI 客户话术陪练」，帮助客服、服务、销售等客户沟通岗位的新人学习和练习，用真实演示和实际数据说明价值。

**使用流程：学习优秀话术 → AI 文字对练 → 查看评分与改进建议 → 考试验证。**

## 按什么顺序做

| 顺序 | 做什么 | 做到什么程度 |
|---|---|---|
| 1. 跑通现有项目 | 验证登录审核、数据库、真实模型和文字对练流程 | 能完成一次文字练习并生成报告 |
| 2. 做好一个业务场景 | 选典型问题，整理客户画像、常见异议和评分标准 | 客户反应合理，点评具体、符合业务规范 |
| 3. 验证录音与知识库 | 授权录音转写分析、审核发布，检索标准话术和业务规范 | 学习内容可用，求助与点评有依据，撤回资料不再检索 |
| 4. 验证考试和使用体验 | 检查组卷、保存、评分、正式考试禁用求助及异常提示 | 员工能独立完成学习、练习与考核 |
| 5. 试用并记录效果 | 收集练习次数、时长、模型成本和员工反馈 | 有真实数据说明效果，估算单独标明 |
| 6. 准备参赛材料 | 录制演示视频，整理成果与提交邮件 | 视频清楚展示问题、操作过程和效果 |

## 功能取舍

- **优先验证：** 一个完整场景、真实模型文字对练、知识库求助与点评、评分报告、稳定部署。
- **验证新增模块：** 账号审核、录音学习、题目审核、考试与自测，复用现有陪练流程。
- **按进度扩展：** 语音输入与播放、更多场景、企业微信补充入口、多格式资料解析和高级检索。

H5 文字对练是当前主流程，浏览器可直接使用；语音为可选能力，不作为当前开发和验收前提。

## 知识库怎么做

参考 LLMentor 的 `know-engine` 设计，在现有 Python 知识库基础上完善：**资料导入 → 分块 → 按场景检索 → 用于求助和点评 → 展示来源**。

后台能看见导入状态和生效内容。客户与教练分别使用所需信息，练习中的求助不能泄露客户隐藏需求或评分答案。

## 接手后需确认

已有转写与事件存储、幂等导入、管理员核对及审核页面已实现。现在可逐条核对真实样例、完善提取标准；随后接真实模型批量提取、隐私与政策核验、版本启用，最后接向量检索和有来源的生成。正式知识以优秀录音为唯一真实来源。

- 模型和数据库的实际可用配置；核对 `.env.example`，不把密钥写入文档。
- 主演示场景、业务评分标准、资料授权与可展示范围。
- 注册审核、文字对练、录音学习发布和完整试卷的真实联调结果。

# 比赛交付

## 提交清单

- 视频不超过 5 分钟，配语音或字幕，以邮件附件提交。
- 邮件标题和视频名称：作品名称+姓名+工号。
- 邮件正文：作品背景、实际成果、设计及应用时间。
- 收件邮箱：hr@zhongruigroup.com；提交时间以比赛通知为准。

## 视频顺序

业务痛点 → 一次实际对练 → 评分与知识依据 → 学习或考核能力 → 实测效果与成本。

只展示已验证的能力，使用虚构或已脱敏素材。没有试点数据时如实写测试结果，不填写虚构人数、提升比例或节省金额。

## 正文填写提示

- 背景：新人在哪类沟通任务中需要练习，目前带教有什么困难。
- 成果：已经实现且验证了什么，试用情况和实际反馈如何。
- 时间：填写真实设计和应用时间。

成本按实际启用的服务统计，文字对练以模型调用费用为主；启用语音时再计入语音费用。与人工比较时写明带教时长和人力单价的来源；计算出的节省额标为估算。
